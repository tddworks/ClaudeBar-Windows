# The HUD Implementation Plan

> **For Claude:** REQUIRED SUB-SKILL: Use superpowers:executing-plans to implement this plan task-by-task.

**Goal:** Build the HUD of [the design](2026-10-13-hud-design.md): an always-on-top, never-focus-keeping Mica window with each signed-in tool's limits, its settings, the taskbar dot and the crossing notifications.

**Architecture:** What a limit *says* is computed in Swift, in `ClaudeBarWindows`, from ClaudeBar's own `Quotas` types and rules. That covers status under the person's policy, pace and the expected-pace tick, so a limit reads the same as on the Mac. It crosses the C interface as JSON, as the Leaderboard does. The C# app owns the window: its Win32 flags, the kept-active Mica, placement, hiding and handing focus back. Unit tests cover Swift's reading (Swift Testing) and the C# geometry (MSTest). `scripts/check-hud.ps1` checks the window's Win32 behaviour on a Windows PC, as the spike did.

**Tech Stack:** Swift 6.3 (ClaudeBarKit's `Quotas`), C# / WinUI 3 (Windows App SDK packages as in `app/ClaudeBar.csproj`), Win32 (`user32`, `dwmapi`, `shell32`), MSTest, Windows PowerShell 5.1.

---

## Before you start

- Read [the design](2026-10-13-hud-design.md), [the mockup](../../design-concept/hud/index.html) and [what Windows does](../../design-concept/hud/research.md). - Build: `.\build.ps1` on the Windows PC, which builds the Swift side, then publishes the app. Swift tests: `cd native; swift test`, from a shell with the MSVC environment loaded (README).

Those need their own design there, an issue first (CONTRIBUTING). Phase A below builds and tests everything else on the branch `feat/hud`. Phase C wires the real limits and opens the PR. Nothing here ships a HUD that shows sample data.

```swift
import Foundation
import Quotas

/// What the HUD shows (docs/plans/2026-10-13-hud-design.md): for each signed-in
/// tool, a line per limit, read through ClaudeBar's own rules (status under
/// the person's policy, pace, the expected-pace tick), so a limit reads the
/// same on Windows as in the Mac's popover. Numbers and dates, not words:
/// the app formats them in the person's language.
public struct HudReading: Equatable, Sendable, Encodable {
    public struct Line: Equatable, Sendable, Encodable {
        /// The window's short name: the quota's compact title, or "5h", "7d".
        public let window: String
        /// The share left, as the Mac shows it (whole percent, rounded down).
        public let percentLeft: Int
        public let resetsAt: Date?
        /// The window's length in seconds, when the data source states it.
        public let windowSeconds: Double?
        /// `healthy`, `warning`, `critical` or `depleted`, under the person's policy.
        public let status: String
        /// Ahead of an even pace: the Mac's "Running hot".
        public let runningHot: Bool
        /// Where the bar would end at an even pace (0–100), when the window is known.
        public let tick: Double?
        /// Whether the strip shows it: the tool's shortest window, or a limit that needs you.
        public let strip: Bool
    }

    public struct Tool: Equatable, Sendable, Encodable {
        public let id: String
        public let lines: [Line]
        /// When the earliest of its limits at 0 comes back.
        public let outUntil: Date?
        public let runningHot: Bool
    }

    public let tools: [Tool]
    /// The worst status of every line, for the taskbar dot.
    public let worst: String

    public init(snapshots: [UsageSnapshot], policy: StatusPolicy) {
        var worst = QuotaStatus.healthy
        tools = snapshots.map { snapshot in
            // A balance with no ceiling has no share to draw; the window shows it.
            let quotas = snapshot.quotas.filter { !$0.isBalance && $0.percentLeft != nil }
            let shortest = quotas.min { ($0.windowDuration ?? .infinity) < ($1.windowDuration ?? .infinity) }
            let lines = quotas.map { quota in
                let status = quota.status(under: policy)
                worst = max(worst, status)
                let hot = quota.pace == .ahead
                return Line(
                    window: quota.compactTitle ?? quota.quotaType.shortLabel,
                    percentLeft: Int(quota.percentLeft ?? quota.percentRemaining),
                    resetsAt: quota.resetsAt,
                    windowSeconds: quota.windowDuration,
                    status: status.name,
                    runningHot: hot,
                    tick: quota.expectedProgressPercent(mode: .remaining),
                    strip: quota == shortest || status != .healthy || hot
                )
            }
            let out = zip(quotas, lines).filter { $0.1.status == "depleted" }.compactMap { $0.0.resetsAt }.min()
            return Tool(id: snapshot.providerId, lines: lines, outUntil: out, runningHot: lines.contains(where: \.runningHot))
        }
        self.worst = worst.name
    }
}

private extension QuotaStatus {
    var name: String {
        switch self {
        case .healthy: "healthy"
        case .warning: "warning"
        case .critical: "critical"
        case .depleted: "depleted"
        }
    }
}
```

```csharp
namespace ClaudeBar;

/// A rectangle in physical pixels, as Win32 and AppWindow give them.
internal readonly record struct Box(int X, int Y, int Width, int Height)
{
    internal int Right => X + Width;
    internal int Bottom => Y + Height;
}

internal enum Corner { TopLeft, TopRight, BottomLeft, BottomRight }

/// Where the HUD sits, and when it hides (docs/plans/2026-10-13-hud-design.md).
internal static class HudGeometry
{
    /// The corner of the work area nearest the HUD's centre, where a drag ends.
    internal static Corner Nearest(Box hud, Box work)
    {
        var right = hud.X + hud.Width / 2 > work.X + work.Width / 2;
        var bottom = hud.Y + hud.Height / 2 > work.Y + work.Height / 2;
        return (right, bottom) switch
        {
            (false, false) => Corner.TopLeft,
            (true, false) => Corner.TopRight,
            (false, true) => Corner.BottomLeft,
            _ => Corner.BottomRight,
        };
    }

    /// The HUD at a corner of the work area, `margin` in from its edges, and
    /// never larger than the work area less the margins.
    internal static Box Place(Corner corner, int width, int height, Box work, int margin)
    {
        width = Math.Min(width, work.Width - 2 * margin);
        height = Math.Min(height, work.Height - 2 * margin);
        var x = corner is Corner.TopLeft or Corner.BottomLeft ? work.X + margin : work.Right - margin - width;
        var y = corner is Corner.TopLeft or Corner.TopRight ? work.Y + margin : work.Bottom - margin - height;
        return new Box(x, y, width, height);
    }

    /// Hidden while the window in front is exactly the HUD's screen (full
    /// screen, a game, a video), unless that's the desktop, and during a
    /// presentation. The shell's own busy state isn't used: it missed a
    /// full-screen window on the second screen (research.md).
    internal static bool ShouldHide(Box foreground, bool foregroundIsDesktop, Box hudScreen, bool presentation) =>
        presentation || (!foregroundIsDesktop && foreground == hudScreen);
}
```

### Task 3: Mica that keeps its active look

**Files:**
- Create: `app/KeptActiveMica.cs`

The spike measured the choice (research.md, *Which material*). On an inactive window, Mica is the solid `SolidBackgroundFillColorBase`, and a click on the HUD activates it for a moment, so the system's own Mica would flicker. Kept active, it keeps one wallpaper tint. Acrylic is for transient surfaces and GPU-intensive (Microsoft's guidance), so the HUD doesn't use it. There's no unit test, because only the screen shows it; Task 7's check script captures it.

**Step 1: Write it**

```csharp
using Microsoft.UI.Composition;
using Microsoft.UI.Composition.SystemBackdrops;
using Microsoft.UI.Xaml;
using Microsoft.UI.Xaml.Media;

namespace ClaudeBar;

/// Mica whose configuration stays active. The framework's configuration
/// follows activation, and the HUD is never the active window except for a
/// moment after a click, so the system's own Mica would sit at its solid
/// inactive colour and flicker to the active tint on each click (measured,
/// design-concept/hud/research.md).
internal sealed class KeptActiveMica : SystemBackdrop
{
    private MicaController? _controller;
    private SystemBackdropConfiguration? _configuration;

    protected override void OnTargetConnected(ICompositionSupportsSystemBackdrop target, XamlRoot xamlRoot)
    {
        base.OnTargetConnected(target, xamlRoot);
        _configuration = new SystemBackdropConfiguration { IsInputActive = true, Theme = Theme(xamlRoot) };
        if (xamlRoot.Content is FrameworkElement root)
            root.ActualThemeChanged += (_, _) => { if (_configuration is { } c) c.Theme = Theme(xamlRoot); };
        _controller = new MicaController { Kind = MicaKind.Base };
        _controller.AddSystemBackdropTarget(target);
        _controller.SetSystemBackdropConfiguration(_configuration);
    }

    protected override void OnTargetDisconnected(ICompositionSupportsSystemBackdrop target)
    {
        base.OnTargetDisconnected(target);
        _controller?.RemoveSystemBackdropTarget(target);
        _controller?.Dispose();
        _controller = null;
    }

    private static SystemBackdropTheme Theme(XamlRoot root) =>
        (root.Content as FrameworkElement)?.ActualTheme == ElementTheme.Light ? SystemBackdropTheme.Light : SystemBackdropTheme.Dark;
}
```

### Task 4: Handing focus back after a click

**Files:**
- Create: `app/ForegroundTracker.cs`
- Modify: `app/Win32.cs` (add the imports below)

A click on a WinUI button activates its window, whatever the window's styles say: `WS_EX_NOACTIVATE`, `MA_NOACTIVATE` and `PA_NOACTIVATE` all fail, because WinUI sets the focus itself (measured and traced, research.md). So the HUD remembers the last window outside ClaudeBar to be in front and gives the foreground back to it.

```csharp
namespace ClaudeBar;

/// The window the person was working in: the last foreground window that
/// isn't ClaudeBar's. After a click on the HUD, which activates it (measured,
/// research.md), `GiveBack` returns the foreground there. Windows allows it:
/// ClaudeBar is then the foreground process, and received the last input.
internal sealed class ForegroundTracker : IDisposable
{
    private readonly Win32.WinEventProc _proc;
    private readonly IntPtr _hook;
    private readonly uint _ownProcess = (uint)Environment.ProcessId;
    private IntPtr _last;

    internal ForegroundTracker()
    {
        _proc = (_, _, window, _, _, _, _) => Remember(window);
        _hook = Win32.SetWinEventHook(Win32.EVENT_SYSTEM_FOREGROUND, Win32.EVENT_SYSTEM_FOREGROUND, IntPtr.Zero, _proc, 0, 0, Win32.WINEVENT_OUTOFCONTEXT);
        Remember(Win32.GetForegroundWindow());
    }

    private void Remember(IntPtr window)
    {
        Win32.GetWindowThreadProcessId(window, out var process);
        if (window != IntPtr.Zero && process != _ownProcess) _last = window;
    }

    /// Returns the foreground to the person's window, if there is one.
    internal void GiveBack()
    {
        if (_last != IntPtr.Zero) Win32.SetForegroundWindow(_last);
    }

    public void Dispose() => Win32.UnhookWinEvent(_hook);
}
```

**Step 2: Write the window**

The window's setup is the spike's `BuildHud`, with the measured choices:

```csharp
using Microsoft.UI.Windowing;
using Microsoft.UI.Xaml;
using Windows.Graphics;
using WinRT.Interop;

namespace ClaudeBar;

/// The HUD (docs/plans/2026-10-13-hud-design.md): a borderless tool window,
/// always on top, never activated to show anything, Mica kept active,
/// snapped to a corner of its screen, hidden for full-screen windows.
internal sealed class HudWindow
{
    private const int MarginDip = 12;
    private const int WidthDip = 320;
    private readonly Window _window = new() { Title = "ClaudeBar HUD" };
    private readonly IntPtr _hwnd;
    private readonly ForegroundTracker _foreground;
    private readonly DispatcherTimer _watch = new() { Interval = TimeSpan.FromSeconds(1) };
    private bool _hiddenForFullScreen;

    internal HudWindow(FrameworkElement content, ForegroundTracker foreground)
    {
        _foreground = foreground;
        _window.Content = content;
        _window.SystemBackdrop = new KeptActiveMica();
        var presenter = OverlappedPresenter.Create();
        presenter.IsAlwaysOnTop = Preferences.HudOnTop;
        presenter.IsResizable = false;
        presenter.IsMaximizable = false;
        presenter.IsMinimizable = false;
        presenter.SetBorderAndTitleBar(true, false);
        _window.AppWindow.SetPresenter(presenter);
        _window.AppWindow.IsShownInSwitchers = false;

        _hwnd = WindowNative.GetWindowHandle(_window);
        var ex = (long)Win32.GetWindowLongPtrW(_hwnd, Win32.GWL_EXSTYLE);
        Win32.SetWindowLongPtrW(_hwnd, Win32.GWL_EXSTYLE, (IntPtr)(ex | Win32.WS_EX_NOACTIVATE | Win32.WS_EX_TOOLWINDOW));
        var round = Win32.DWMWCP_ROUND;
        Win32.DwmSetWindowAttribute(_hwnd, Win32.DWMWA_WINDOW_CORNER_PREFERENCE, ref round, sizeof(int));

        // Dragged by its caption region (below); snapped when the drag ends, then
        // the foreground goes back to the person's window, as after a click.
        _subclass = (window, message, wParam, lParam, id, data) =>
        {
            if (message == Win32.WM_EXITSIZEMOVE) { Snap(); _foreground.GiveBack(); }
            return Win32.DefSubclassProc(window, message, wParam, lParam);
        };
        Win32.SetWindowSubclass(_hwnd, _subclass, (UIntPtr)1, UIntPtr.Zero);
        _watch.Tick += (_, _) => FollowFullScreen();
    }

    private readonly Win32.SubclassProc _subclass;

    /// Shows it at its corner, without activating it.
    internal void Show(int heightDip)
    {
        Place(heightDip);
        _window.AppWindow.Show(false);
        _watch.Start();
    }

    internal void Hide()
    {
        _watch.Stop();
        _window.AppWindow.Hide();
    }

    /// After any action a click on the HUD runs: the person's window again.
    internal void AfterClick() => _foreground.GiveBack();

    private double Scale => Win32.GetDpiForWindow(_hwnd) / 96.0;

    private DisplayArea Screen => DisplayArea.GetFromWindowId(_window.AppWindow.Id, DisplayAreaFallback.Nearest);

    private void Place(int heightDip)
    {
        var work = Screen.WorkArea;
        var box = HudGeometry.Place(Preferences.HudCorner, (int)(WidthDip * Scale), (int)(heightDip * Scale),
                                    new Box(work.X, work.Y, work.Width, work.Height), (int)(MarginDip * Scale));
        _window.AppWindow.MoveAndResize(new RectInt32(box.X, box.Y, box.Width, box.Height));
    }

    /// A drag ended: the nearest corner of the screen it ended on.
    private void Snap()
    {
        var work = Screen.WorkArea;
        var p = _window.AppWindow.Position;
        var s = _window.AppWindow.Size;
        Preferences.HudCorner = HudGeometry.Nearest(new Box(p.X, p.Y, s.Width, s.Height), new Box(work.X, work.Y, work.Width, work.Height));
        Place((int)(s.Height / Scale));
    }

    private void FollowFullScreen()
    {
        var foreground = Win32.GetForegroundWindow();
        Win32.GetWindowRect(foreground, out var r);
        var name = new System.Text.StringBuilder(64);
        Win32.GetClassNameW(foreground, name, 64);
        var isDesktop = name.ToString() is "Progman" or "WorkerW";
        Win32.SHQueryUserNotificationState(out var state);
        var screen = Screen.OuterBounds;
        var hide = HudGeometry.ShouldHide(new Box(r.Left, r.Top, r.Right - r.Left, r.Bottom - r.Top), isDesktop,
                                          new Box(screen.X, screen.Y, screen.Width, screen.Height), state == Win32.QUNS_PRESENTATION_MODE);
        if (hide == _hiddenForFullScreen) return;
        _hiddenForFullScreen = hide;
        if (hide) _window.AppWindow.Hide(); else _window.AppWindow.Show(false);
    }
}
```

`Win32.RECT` already exists (`Left, Top, Right, Bottom`). Add `internal const uint WM_EXITSIZEMOVE = 0x0232;` with the imports.

**Dragging:** the HUD has no title bar, so give it a caption region, as `MainWindow` does with `SetTitleBar`. Use `InputNonClientPointerSource.GetForWindowId(_window.AppWindow.Id)`: `NonClientRegionKind.Caption` over the card's top 12 px and footer, and `Passthrough` over each button, so buttons stay clickable. Dragging a no-activate window by its caption is **unmeasured**. Add it to Task 7's script: the HUD moves, snaps to the corner nearest the drop, and the person's window is in front afterwards.

### Task 6: What the HUD draws

**Files:**

Layout, from the mockup (`design-concept/hud/index.html`, section 2):
- **Card:**
  - 14 px left and right padding.
  - Per tool: a `StackPanel` with an 8 px `Ellipse` in the tool's colour, then its name in `BodyStrongTextBlockStyle`. The flag sits on the right in `CaptionTextBlockStyle`: *Running hot* in `SystemFillColorCautionBrush`, *Out until HH:mm* in `SystemFillColorCriticalBrush`, *Signed out* and *Couldn't read* in `TextFillColorSecondaryBrush`.
  - Per line: a 4-column `Grid` (22, *, 44, 62 effective px).
    - The window name: caption, `TextFillColorSecondaryBrush`.
    - The bar: a 4 px `Border` track with a fill and a 2 × 10 px tick, using `AccentFillColorDefaultBrush`, the caution brush or the critical brush.
    - The share: BodyStrong, right-aligned, `Typography.NumeralAlignment` tabular.
    - The time to reset: caption, `TextFillColorSecondaryBrush`, tabular.
  - The footer: a 1 px `DividerStrokeColorDefaultBrush` top border, then today's tokens, the place and the reading's age, in `TextFillColorSecondaryBrush`.

- **States:** reading for the first time (skeleton rows at their final height), offline (the shares in `TextFillColorSecondaryBrush` instead of primary, the bars at 45% opacity, and the footer says *Offline · as of HH:mm* with *Retry*), signed out and couldn't read (one caption line with the action), nothing found (a sentence and *Choose tools*).

- **Every clickable element** calls `HudWindow.AfterClick()` when its action is done. The right-click `MenuFlyout` calls it when it closes.
